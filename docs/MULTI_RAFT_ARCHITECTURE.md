# AiDb Multi-Raft 架构图解

**更新时间**: 2025-11-20

本文档提供 Multi-Raft + Sharding 架构的可视化说明，帮助快速理解系统设计。

---

## 📊 架构对比

### 当前架构：单 Raft Group

```
┌─────────────────────────────────────────────────────────────┐
│                        集群视图                              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  节点1 (Leader)         节点2 (Follower)      节点3 (Follower)│
│  ┌─────────────┐       ┌─────────────┐       ┌─────────────┐│
│  │  Raft Log   │       │  Raft Log   │       │  Raft Log   ││
│  │  [1][2][3]  │───────│  [1][2][3]  │───────│  [1][2][3]  ││
│  └──────┬──────┘       └──────┬──────┘       └──────┬──────┘│
│         │                     │                     │        │
│  ┌──────▼──────┐       ┌──────▼──────┐       ┌──────▼──────┐│
│  │     DB      │       │     DB      │       │     DB      ││
│  │  [全量数据]  │       │  [全量数据]  │       │  [全量数据]  ││
│  │   1TB       │       │   1TB       │       │   1TB       ││
│  └─────────────┘       └─────────────┘       └─────────────┘│
│                                                              │
│  可用容量: 1TB                                               │
│  写放大: 3x (所有节点写入)                                    │
│  扩展性: ✗ 无法横向扩展                                       │
└─────────────────────────────────────────────────────────────┘
```

**问题**:
- ❌ 所有节点存储全量数据（1TB × 3 = 1TB 可用）
- ❌ 写放大 = 节点数（3~N）
- ❌ 无法横向扩展容量
- ❌ Leader 单点瓶颈

---

### 目标架构：Multi-Raft + Sharding

```
┌────────────────────────────────────────────────────────────────────────┐
│                            集群视图                                     │
├────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────────────────────────────────────────────────────┐      │
│  │              MetaRaft (Group 0) - 全局唯一                   │      │
│  │  ┌─────────────────────────────────────────────────────┐    │      │
│  │  │  ClusterMeta:                                       │    │      │
│  │  │  • slots[16384]: slot → group_id 映射              │    │      │
│  │  │  • groups: GroupId → (replicas, leader)            │    │      │
│  │  │  • nodes: NodeId → NodeInfo                         │    │      │
│  │  └─────────────────────────────────────────────────────┘    │      │
│  │                                                              │      │
│  │  Leader: 节点1    Followers: 节点2, 节点3                   │      │
│  └──────────────────────────────────────────────────────────────┘      │
│                                                                         │
│  ┌──────────────────────────────────────────────────────────────┐     │
│  │                    Data Raft Groups                          │     │
│  ├──────────────────────────────────────────────────────────────┤     │
│  │                                                              │     │
│  │  Group 1 (slots 0~99)                                        │     │
│  │  ┌────────────┐      ┌────────────┐      ┌────────────┐     │     │
│  │  │ 节点1 (L)   │──────│ 节点2 (F)   │──────│ 节点3 (F)   │     │     │
│  │  │ DB1: 100MB │      │ DB1: 100MB │      │ DB1: 100MB │     │     │
│  │  └────────────┘      └────────────┘      └────────────┘     │     │
│  │                                                              │     │
│  │  Group 2 (slots 100~199)                                     │     │
│  │  ┌────────────┐      ┌────────────┐      ┌────────────┐     │     │
│  │  │ 节点2 (L)   │──────│ 节点3 (F)   │──────│ 节点1 (F)   │     │     │
│  │  │ DB2: 100MB │      │ DB2: 100MB │      │ DB2: 100MB │     │     │
│  │  └────────────┘      └────────────┘      └────────────┘     │     │
│  │                                                              │     │
│  │  Group 3 (slots 200~299)                                     │     │
│  │  ┌────────────┐      ┌────────────┐      ┌────────────┐     │     │
│  │  │ 节点3 (L)   │──────│ 节点1 (F)   │──────│ 节点2 (F)   │     │     │
│  │  │ DB3: 100MB │      │ DB3: 100MB │      │ DB3: 100MB │     │     │
│  │  └────────────┘      └────────────┘      └────────────┘     │     │
│  │                                                              │     │
│  │  ...                                                         │     │
│  │  (总共 16384 个 Groups)                                       │     │
│  └──────────────────────────────────────────────────────────────┘     │
│                                                                         │
│  每个节点存储: ~333MB (1TB / 3 副本)                                    │
│  可用容量: ~333MB × 3 节点 = ~1TB (实际利用率 100%)                     │
│  写放大: 3x (仅副本数)                                                  │
│  扩展性: ✓ 线性横向扩展                                                 │
└────────────────────────────────────────────────────────────────────────┘
```

**优势**:
- ✅ 分片存储：每个节点仅存储部分数据
- ✅ 写放大固定：3~5 倍（副本数）
- ✅ 横向扩展：添加节点线性增加容量
- ✅ 多 Leader：16384 个独立 Leader，无瓶颈

## 🔄 数据流

### 写入流程

```
1. 客户端请求
   ┌─────────────────┐
   │ PUT key=user123 │
   │     value=data  │
   └────────┬────────┘
            │
            ▼
2. Router 计算
   ┌──────────────────────────────┐
   │ slot = crc16("user123") % 16384 = 42
   │ group_id = meta.slots[42] = 1      │
   │ replicas = [节点1, 节点2, 节点3]    │
   └────────┬─────────────────────┘
            │
            ▼
3. 路由到 Group 1 Leader (节点1)
   ┌────────────────────┐
   │  Group 1 Leader    │
   │  ┌──────────────┐  │
   │  │ Raft Propose │  │
   │  └──────┬───────┘  │
   │         │          │
   │         ▼          │
   │  ┌──────────────┐  │
   │  │ Raft Log [N] │  │
   │  └──────┬───────┘  │
   └─────────┼──────────┘
             │
             ▼
4. 复制到 Followers
   ┌────────────┐       ┌────────────┐
   │ 节点2 (F)   │       │ 节点3 (F)   │
   │ Raft Log[N]│       │ Raft Log[N]│
   └────────────┘       └────────────┘
             │               │
             └───────┬───────┘
                     │
                     ▼
5. 应用到 StateMachine
   ┌───────────────────────────┐
   │ ShardedStateMachine       │
   │  groups[1].apply(entry)   │
   │    └─> DB1.put(key, value)│
   └───────────────────────────┘
             │
             ▼
6. 响应客户端
   ┌─────────┐
   │   OK    │
   └─────────┘
```

### 读取流程

```
1. 客户端请求
   ┌─────────────────┐
   │ GET key=user123 │
   └────────┬────────┘
            │
            ▼
2. Router 计算
   ┌──────────────────────────────┐
   │ slot = crc16("user123") % 16384 = 42
   │ group_id = meta.slots[42] = 1      │
   └────────┬─────────────────────┘
            │
            ▼
3. 本地读取（如果本节点有副本）
   ┌─────────────────────────┐
   │ ShardedStateMachine     │
   │  groups[1].get(key)     │
   │    └─> DB1.get(key)     │
   └─────────┬───────────────┘
             │
             ▼
   ┌─────────────┐
   │ value=data  │
   └─────────────┘

   OR

3. 远程读取（如果本节点无副本）
   ┌────────────────────────┐
   │ RPC to 节点1 (Leader)   │
   │  └─> get(key)          │
   └────────┬───────────────┘
            │
            ▼
   ┌─────────────┐
   │ value=data  │
   └─────────────┘
```

## 🔀 Slot 迁移流程

### 迁移状态机

```
     ┌──────┐
     │ Idle │
     └───┬──┘
         │ MIGRATE slot from_group to_group
         ▼
  ┌──────────────┐
  │  Preparing   │
  └───┬──────────┘
      │ 1. 目标 Group 进入 IMPORTING
      │ 2. 源 Group 进入 MIGRATING
      ▼
  ┌──────────────┐
  │  Migrating   │◄─────────┐
  └───┬──────────┘          │
      │                     │
      │ 批量迁移 keys       │ 错误重试
      │ GET → PUT → DEL     │
      │                     │
      ▼                     │
  ┌──────────────┐          │
  │  Syncing     │──────────┘
  └───┬──────────┘
      │ 双写到源和目标
      │ 异步捉补差异
      ▼
  ┌──────────────┐
  │  Finishing   │
  └───┬──────────┘
      │ 1. 更新 MetaRaft slot mapping
      │ 2. 关闭双写
      │ 3. 删除源 Group 数据
      ▼
  ┌──────────────┐
  │  Complete    │
  └──────────────┘
```

### 详细流程

```
时间轴           源 Group (1)              目标 Group (2)              MetaRaft
  │
  │ T0
  ├─────────► 正常服务                    正常服务
  │            slot 42 → Group 1
  │
  │ T1: 发起迁移
  ├─────────────────────────────────────────────────────────────► propose:
  │                                                                  MIGRATE slot 42
  │                                                                  from 1 to 2
  │
  │ T2: 状态变更
  ├─────────► state = MIGRATING          state = IMPORTING    ◄──── apply:
  │            新写入 → 双写                新写入 → 接收               update states
  │
  │ T3: 批量迁移
  ├─────────► SCAN keys in slot 42
  │            ├─> GET key1 → value1
  │            ├─> GET key2 → value2  ──────────────────────► PUT key1 → value1
  │            └─> ...                ──────────────────────► PUT key2 → value2
  │
  │ T4: 确认迁移
  │                                                        ◄─── ACK: keys received
  ├─────────► DELETE key1
  │            DELETE key2
  │            ...
  │
  │ T5: 捉补阶段
  ├─────────► 扫描差异（新写入的 keys）
  │            ├─> GET key_new1      ──────────────────────► PUT key_new1
  │            └─> ...
  │
  │ T6: 完成迁移
  ├─────────────────────────────────────────────────────────────► propose:
  │                                                                  UPDATE_SLOTS
  │                                                                  slots[42] = 2
  │
  │ T7: 切换路由
  ├─────────► state = Idle              state = Idle       ◄──── apply:
  │            停止双写                   正常服务                   slots[42] = 2
  │            删除 slot 42 数据
  │
  │ T8
  ├─────────► 正常服务                    正常服务
  │            (不再处理 slot 42)         slot 42 → Group 2
  │
```

## 📈 扩展性分析

### 容量扩展

```
集群规模           当前架构              Multi-Raft 架构
─────────────────────────────────────────────────────────
3 节点 × 1TB      1TB 可用              ~1TB 可用
10 节点 × 1TB     1TB 可用              ~3.3TB 可用
100 节点 × 1TB    1TB 可用              ~33TB 可用
1000 节点 × 1TB   1TB 可用              ~333TB 可用

扩展比例          1:1 (无扩展)           1:N/3 (线性扩展)
```

### 性能扩展

```
指标               当前架构                   Multi-Raft 架构
─────────────────────────────────────────────────────────────
单 key 写延迟      随节点数增加               固定 < 1ms
写吞吐量           ~10K ops/s (单 Leader)    ~100K~1M ops/s (多 Leader)
读吞吐量           ~100K ops/s               ~1M~10M ops/s
QPS 扩展           不扩展                     近线性扩展
```

### 成本对比

```
场景: 100 节点，每节点 1TB 磁盘

当前架构:
  • 总磁盘: 100TB
  • 可用容量: 1TB (全量复制)
  • 利用率: 1% (99TB 浪费)
  • 成本: 100TB × $0.1/GB/月 = $10,000/月

Multi-Raft 架构 (3 副本):
  • 总磁盘: 100TB
  • 可用容量: ~33TB (分片 + 3 副本)
  • 利用率: 33%
  • 成本: 100TB × $0.1/GB/月 = $10,000/月
  • 实际成本降低: 66% (相同成本下容量增加 33 倍)
```

## 🎯 总结

Multi-Raft + Sharding 架构通过以下关键设计实现真正的横向扩展：

1. **MetaRaft**: 全局唯一元数据管理，保证一致性
2. **16384 Slots**: 细粒度分片，灵活迁移
3. **独立 Raft Groups**: 每个 Group 独立选举和复制
4. **ShardedStateMachine**: 每个 Group 独立 DB 实例
5. **智能路由**: key → slot → group_id 自动路由
6. **在线迁移**: 零停机 slot 迁移，动态负载均衡

**最终效果**:
- ✅ 容量随节点数线性增长 (1/3 ~ 1/5)
- ✅ 写放大固定 (3~5 倍，而非 N 倍)
- ✅ 延迟稳定 (< 1ms，不受节点数影响)
- ✅ 吞吐量线性扩展 (多 Leader 并行)
- ✅ 生产可用 (完整监控、运维工具)
